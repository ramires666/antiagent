## Приёмка и активация

Изменения исполнителя принимаются только после независимого diff review и
релевантных тестов root. Исторические незакоммиченные изменения сохраняются;
Пользователь отдельно разрешил commit/push готовых изменений. Тесты и сборка, меняющая package metadata,
не запускаются одновременно.

После исходников обязателен полный handoff: закрыть все Codex, выполнить
`py -m antiagent_upgrade`, запустить новый верхнеуровневый Codex, doctor,
строгий smoke_mcp.py и bounded live marker smoke. Для браузера — отдельная
проверка по BROWSER.md. Исходники и unit-тесты не означают активированную установку.

Сохранённые ограничения из завершённого persistent-manager плана: после гибели
MCP нельзя присоединить запущенный CLI-процесс без отдельного supervisor;
forked transcript и native UI-thread остаются функциями Codex; durable store
сохраняет snapshots, но не заменяет supervisor. Автоматическое делегирование
задаётся инструкциями. Эти ограничения не являются незавершёнными пунктами
первой поставки. Старое намерение push не считается текущим разрешением на push.
